# 시스템 경계와 아이디어 계보

서로 다른 시기의 모든 구현을 하나의 현재 제품 구조로 합친 그림이 아닙니다. 공통으로 지키려 한 책임 경계를 정리했습니다.

## 제품 입력과 시선 연구를 구분

```mermaid
flowchart LR
  A[카메라 관측] --> B[눈 상태와 파형 사건]
  B --> C[공통 의미 해석]
  C --> D[제품과 빌드 어댑터]
  D --> E[Roll 세로 이동]
  D --> F[Page 가로 넘김]
  D --> G[Game 행동]
  A --> H[랩의 명시적 로컬 수집]
  H --> I[시각 결합과 자료 역할 검증]
  I --> J[오프라인 모델 비교]
  J --> K[좌표 또는 방향 관측]
  K --> L[별도 제어와 표시 비교]
  L --> M[품질 관문과 디버그 검증]
```

MediaPipe의 관측, 자체 방향 모델, 보는 힘 제어와 Unity 표시를 같은 모델이라고 부르지 않습니다. Roll과 Page·Game의 수집 경로 차이도 남아 있어 공통 모듈을 쓴다는 말만으로 모든 실행이 같다고 가정하지 않습니다. 연구 수집과 미채택 모델은 제품에 자동 유입되지 않게 구분합니다.
