# 아이디어와 해결 과정의 재검토

기준일: 2026-10-15. 첫 공개본 `d8f4fdf`의 PDF와 GitHub 문서를 작성자가 제공한 대화 및 날짜별 개발·연구 기록에 다시 대조했습니다. 모델이나 기기 성능 시험을 새로 실행한 작업은 아닙니다.

## 고친 부분

1. **흰 화면과 흰자를 한 인과관계로 묶지 않았습니다.** 밝은 화면을 관찰 조건으로 쓰자는 제안과 흰자 변화를 입력으로 쓰자는 제안은 별도 갈래입니다. 전자가 곧 후자의 직접 계기였다는 식의 연결을 제거했습니다.
2. **얼굴 각도의 측정 수준을 정확히 썼습니다.** 누락을 고친 값은 MediaPipe 얼굴 변환행렬에서 계산한 자세 추정값입니다. 외부 장비로 잰 실제 얼굴 각도나 물리적 시선 정답이 아닙니다. 과거 947행의 누락과 새 346행의 연결 확인은 유지했습니다.
3. **고정 조건부터 보자는 작성자의 결정을 보강했습니다.** 폰과 사용자를 고정하고 흔들림·먼 거리 문제를 뒤로 미룬 뒤, 랩에서 기본 정확도를 먼저 확인하자는 순서를 추가했습니다. 같은 입력 재대입과 다음 프레임 평가도 구분했습니다.
4. **테두리 보정에서 전체 화면 수집으로 넓힌 제안을 넣었습니다.** 귀여운 움직이는 표적, 모서리까지의 범위, 측정 피로와 짧은 반복, 전체 화면을 빠르게 따라보자는 제안을 연결했습니다. 이후 필수 개인 보정에 반대한 결정과 모순되는 것처럼 쓰지 않았습니다.
5. **얼굴 움직임 입력과 시선 추론을 나눴습니다.** 얼굴을 돌려 에임을 움직이는 제안, 얼굴을 눈의 확장으로 보는 가정, 얼굴에서 먼저 추론하고 눈으로 수정하는 모델을 같은 성공으로 합치지 않았습니다.
6. **시선과 깜빡임 실험의 뜻을 명확히 했습니다.** 화면 안·밖·상단을 보며 깜빡이는 제안과 개인 등록 제거 요구를 보강했습니다. 당시 외부 시험의 정지·재개 대상은 눈 입력이며 동영상 재생 버튼을 직접 제어한 기능이 아닙니다.
7. **ON/OFF를 제안에만 그친 것처럼 쓴 부분을 고쳤습니다.** 랩에 실제로 구현한 조작 의도 게이트와, 눈뜸 프레임이 OFF보다 먼저 도착해 포인터가 튀는 순서 버그의 수정 과정을 추가했습니다. 합성 문법·수명 검사와 실제 눈 토글 성공률은 구분했습니다.
8. **주시안 실험의 분모를 보강했습니다.** 입력 복구 2,025관측과 여섯 촬영 731평가관측의 점수는 다릅니다. 의학적 주시안 진단이 아니라 한쪽 눈·평균·양안 분리의 개발 비교라는 한계를 유지했습니다.
9. **공통 해석기와 어댑터 분리 요구를 구체화했습니다.** 제품별 행동과 Debug·R8·Production별 진단의 차이를 구분하고, 여러 접근성을 꺼서 시험 조건을 바꾸는 해결에 반대했던 요구도 추가했습니다. 모든 설치 조합을 검증했다고 쓰지는 않습니다.
10. **시험 도구가 만든 실패도 넣었습니다.** 기본 UI 자동화 조회가 접근성 연결을 억제했던 부작용과 해당 조회를 중단한 기록을 추가했습니다. 설정이 켜진 상태, 실제 서비스 연결, 카메라 소유권은 서로 다릅니다.
11. **사용성 결정과 제안 단계를 복원했습니다.** 마우스처럼 필요할 때 쓰는 도구라는 기준, 자동 절전 옵션, 고정된 가운데 연습 영역과 앱별 방향 설명, 품질 우선·발열 차단 반대, 데드존 제안을 추가했습니다. 별도 데드존 후보까지 통과했다고 주장하지 않습니다.
12. **초기 성공 표현과 근거 연결을 고쳤습니다.** 6월의 모바일 HTTPS·카메라 준비를 당시 미해결 깜빡임→스크롤 성공으로 넓힌 계보 표현을 수정했습니다. 특허·성능·잠금 재개·기기 교차 재생·출시 사례의 근거 번호도 실제 해당 문서로 연결했습니다. Roll의 잠금 수정은 Page의 신규 수정으로 합산하지 않습니다.
13. **제출용 PDF에서 작성자용 편집 지침을 뺐습니다.** 「이력서에 옮길 때 구분할 표현」과 표현 비교 표를 제거하고 마지막 항목을 21번으로 맞췄습니다. 본문의 실험 결과, 미완료 범위와 특허 상태는 유지했습니다. 표현 비교는 별도 구조 문서의 참고 자료로만 남겼습니다.

- 눈 입력 문법은 실제 의도를 항상 알아내는 독심 기능이 아닙니다. 같은 완성 파형으로 관측되면 자연 깜빡임도 통과할 수 있습니다.
- 일부 조건의 점수 상승, 정밀 좌표, 방향 분류, 실제 게임 조작감은 서로 다른 성과입니다. 미채택 후보의 좋은 숫자를 제품 정확도로 만들지 않았습니다.

- 처음 제안한 날짜가 확인되지 않은 아이디어에는 날짜를 만들지 않습니다. 실험 기록일과 제안 순서는 구분합니다.
